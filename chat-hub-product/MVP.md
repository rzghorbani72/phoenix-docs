# MVP Scope
_Last updated: 2026-10-27_

## Hypothesis
**اگر کارمندان با لاگین سازمانی به مدل‌های جهانی با کیفیت برابر دسترسی داشته باشند و سهمیه‌شان را شفاف ببینند، ≥ ۷۰٪ از ۱۰۰ کاربر پایلوت بعد از ۴ هفته هنوز هفتگی فعال‌اند و ترافیک آن‌ها به سرویس‌های AI خارجی ≥ ۳۰٪ کم می‌شود. همچنین ≥ ۷ از ۱۰ dev پایلوت کلید Hub را در IDE نگه می‌دارند.**

## In scope
- **SSO + لاگین اجباری** — بدون هویت، فرضیه قابل اندازه‌گیری نیست.
- **چت با ۳ ارائه‌دهنده + انتخاب مدل** — بخش «کیفیت برابر» فرضیه.
- **تاریخچه‌ی سرور + آپلود فایل** — بدون این‌ها کیفیت حس‌شده پایین‌تر از ChatGPT است.
- **بودجه‌ی flat per-user + صفحه‌ی Usage** — بخش «سهمیه‌ی شفاف» فرضیه + محافظ مالی پایلوت.
- **API key برای dev** — بخش dev فرضیه.
- **Trace metadata + TTFT + 👍/👎** — ابزار اندازه‌گیری خود فرضیه.
- **Guardrail shadow (متن)** — هزینه‌اش کم است و داده‌ای جمع می‌کند که بعداً با هیچ قیمتی نمی‌شود خرید.

## Explicitly cut
- **سلسله‌مراتب واحد سازمانی** — ۱۰۰ نفر پایلوت را با team flat مدیریت می‌کنیم. فرضیه به آن وابسته نیست.
- **داشبورد ادمین کامل** — در پایلوت، ادمین UI داخلی LiteLLM یا اسکریپت کافی است.
- **Guardrail enforce و چندرسانه‌ای** — enforce روی پایلوت فقط با false positive فرضیه‌ی کیفیت را آلوده می‌کند.
- **Files API برای dev** — dev‌های پایلوت با chat completions کار می‌کنند.
- **Auth API برای محصولات دیگر، Agents، Memory، Auto routing** — هیچ‌کدام برای جواب دادن به فرضیه لازم نیستند.

## What "done" looks like
- ۱۰۰ کاربر از ۳ واحد + ۱۰ dev، ۴ هفته.
- داشبورد (حتی یک کوئری SQL) که WAU هفتگی، نرخ 👍، p95 TTFT و مصرف per-user را نشان دهد.
- مقایسه‌ی ترافیک پروکسی همان ۱۰۰ نفر، قبل و بعد.
- **تصمیم Go:** WAU ≥ ۷۰٪ و 👍 ≥ ۸۵٪ ← GA. **Pivot:** اگر 👍 پایین است، مشکل کیفیت یا مدل است، نه فیچر.
