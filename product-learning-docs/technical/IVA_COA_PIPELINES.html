The whole system

IVALive voice agent, from zero to hero

  1. Worker prewarm. Each LiveKit worker process loads Silero VAD and builds one agent session up front: manual turn handling, endpointing 0.5–3 s, VAD barge-in after 0.4 s, and 3 retries with a 10 s timeout for STT, LLM and TTS.python/chatbot-iva-agent/src/main.py · prewarm, agent_session_factory
  2. The call reaches a room. The operator network and SBC deliver SIP to LiveKit (that edge is not in this repo). LiveKit creates a room with a SIP participant whose identity carries the caller number, e.g. sip_+98912….main.py · extract_phone_number, normalize_phone_number
  3. Dispatch. The worker joins audio-only, waits for the participant, normalises the phone to 98… and chooses the agent class from AGENT_LLM_STRUCTURE: agentlib (aiva) or legacy chatbotlib.main.py · dispatch, agent_factory
  4. Session and greeting. The agent calls aiva POST /api/v1/chat/session {phone}. aiva gets or creates the user, opens a Session and has GreetingAgent write a greeting from the user's long-term memory.python/aiva/aiva/chat/views/session.py
  5. Go live. The session starts, waits briefly for the RTP path to settle, then speaks the greeting. Optional ambient and "thinking" sounds start, and LiveKit Egress begins recording participant and agent tracks to MinIO bucket chatbot-mci-iva.src/entrypoint.py · run, _setup_egress
  6. Turn loop. Caller audio → VAD → STT → end-of-turn → aiva /chat/completions streamed over SSE → TTS sentence by sentence → back to the caller. See figures 3 and 4.src/agents/agentlib.py · stt_node, _get_llm_client
  7. Hearing and deciding when you stopped. Silero VAD decides who is talking (speech starts at probability 0.5, needs 0.5 s of speech, ends after 1 s of silence, keeps 2 s of padding before speech). STT gets each utterance with X-Request-ID = session_id. End of turn is fixed endpointing (0.5 s minimum, 3 s maximum) unless AGENT_TURN_MODEL is set: mci posts the last 6 turns plus the new message to the MCI turn model, and openai asks an LLM for a 0–1 probability. Below 0.5 the agent keeps waiting.src/main.py · prewarm · src/utils/mci_turn_detector.py · openai_turn_detector.py · config.py:62-122
  8. Speaking back. The streamed answer is cut into sentences on ". " (configurable) so TTS can start on the first sentence while the LLM is still writing. Each sentence goes to an OpenAI-compatible TTS (default model tts-1, speed 1.0); HTTP 204 is in the non-retryable list, so it is never retried.src/utils/sentence_tokenizer.py · src/utils/tts.py · config.py:36-43, 160-167, 382-388
  9. Guards while talking. Repeated empty transcripts trigger a non-speech prompt; silence past the away timeout starts a reminder loop that ends the call after N tries; barge-in cuts TTS.agentlib.py · _check_non_speech, _user_away_loop
  10. Ending. exit_tool, redirect_to_human_agent, the user-away exit, or a hangup closes the room and runs the shutdown callback.agentlib.py · redirect_to_human_agent, _call_sip_redirect_api
  11. Summary out. One SessionSummarySchema goes to Kafka chatbot-mci-iva. Recording paths are the real object keys, or failed / disabled when egress did not run, and grogu drops a call whose track says failed. The same message feeds COA analytics through grogu.
  12. Memory for next time. aiva's memory consumer (10 workers, manual offset commit) reads aggregated events from chatbot-mci-iva-intent, keeps only type=message turns, and asks the memory agent to rewrite user.memory from the previous memory plus this call. On failure it seeks back and retries after 5 s. The next call's greeting, classifier and clarifying prompts all read that memory.entrypoint.py · _log_summary, _create_kafka_message · aiva/memory/management/commands/aiva_consume_kafka.py

How a call ends

Exit

aiva's intent branch returns an exit_tool call after "ممنون از تماس شما، خداحافظ". The agent hangs up; the summary records exit=true.

Redirect to a human

The agent reads the SIP Via, Call-ID and X-channelId headers and posts a SIP MESSAGE through sip-messager (destination 6040 by default), then deletes the room. If headers are missing it says the failure message and records redirect_status=failed.

Caller goes quiet

After AGENT_USER_AWAY_TIMEOUT (10 s) the agent asks the LLM for a reminder in signal mode and repeats up to the threshold, then speaks an exit line and closes the room. Speaking cancels the loop.

Noise, not speech

When STT keeps returning empty final transcripts, the agent counts them and, at the threshold, triggers a signal call so the caller hears a prompt instead of silence.

One message per call, published at shutdown. It is the contract between the two pipelines.

COACall analytics, from zero to hero

  1. Three inputs. Human-agent calls arrive as {call_id, online} on the ASR call topic, AI calls as IVA session summaries, and support tickets on a ticket topic. Each input runs its own grogu deployment.golang/grogu/internal/grogu/app.go · initializeKafkaConsumers
  2. Get the audio. Telc: download the WAV from the TelC file API and store it in the COA MinIO bucket; if TelC sent no usable duration, read it from the file, and calls of 1 s or less become invalid. IVA: download the caller and agent .ogg tracks in parallel, turn each file into a single mono channel (pan takes the left channel of that source file, which holds only one speaker), and join them into one stereo MP3 (8 kHz, 16 kbps) with the caller on the left channel (ch1) and the agent on the right (ch2). See the channel figure below.internal/call/service.go · uploadVoiceFile, downloadVoiceTracks · internal/voice/merge.go
  3. Transcribe. The stereo file is posted to an OpenAI-style transcription endpoint with x-request-id = call_id, optional include=emotion and gender, retried with backoff behind a circuit breaker. The service behind it (voice-segmenter by its matching response shape) splits the channels, runs VAD on each, transcribes every speech chunk, and returns segments with channel, start, end, text, emotion, gender.internal/asr/service.go · golang/voice-segmenter
  4. Check and enrich. No segments, or no caller (ch1) text on an IVA call, marks the call invalid; a Telc call where only ch1 speaks is flagged agent-silent. For every pair of segments on different channels that overlap longer than VOICE_OVERLAP_THRESHOLD, the channel that started later is marked as the interrupter. IVA calls get fixed fields: call_to = the AI agent id, access_code 9990, service_no = caller phone, times converted to Asia/Tehran. MyMCI adds an account overview when enabled, sharing one login token across pods through a Redis lock.call/service.go · isAllCh1NoCh2, addAccountOverview · internal/mymci/service.go
  5. Hand off. The result goes to the Kafka call topic. Failures go to the dead_letter table, and a worker retries them every minute, up to 10 times.grogu/worker.go · sendResultToKafka · internal/deadletter/
  6. Analyse. An AI tagging engine outside this repo consumes the call topic and writes sentiment, bad words, greeting and farewell, satisfaction, category and subcategory, summary, suggestions and topics into ClickHouse.fields read by python/coa-api/coa/apps/main/services/sync.py · _fetch_updated_records
  7. Copy to Postgres. coa-api daemons poll ClickHouse and upsert calls, call_ai_tags and tickets, marking calls succeed. Other loops sync category edits, failures, canonical mappings and trends.coa/apps/main/management/commands/* · apps/trends/management/commands/trend_sync.py
  8. Serve. coa-api exposes call search, recordings, thematic and special analysis, expert and IVA dashboards, trends and tickets; coa-ui renders them; aqa answers natural-language questions with SQL on ClickHouse.coa/apps/*/urls.py · javascript/coa-ui · python/aqa
  9. Retire. archive_old_calls dumps weekly windows older than the retention limit, uploads to MinIO, and deletes only after the upload succeeds.coa/apps/main/management/commands/archive_old_calls.py

The IVA dashboard closes the loop: /iva/dashboard/metrics counts call_ai_tags rows whose agent_id is the AI agent and reports total calls, referenced calls, duration and the satisfied share. That is how a live IVA call ends up as a number on a COA chart.

Gaps and things to know

  • not in repoThe AI tagging engine that turns ASR segments into ClickHouse tags. python/coa-ai only exposes silence detection, low-volume detection and speech-to-text endpoints, and has had no commit since 2025-07-13.
  • not in repoThe producer of chatbot-mci-iva-intent, the aggregated events aiva's memory consumer reads.
  • not in repoThe producer of the MinIO trend snapshots, and the telecom edge (operator core, SBC, SIP proxy) in front of LiveKit.
  • riskaiva chat views set permission_classes = (); protection relies on the gateway.
  • riskThe memory phone whitelist is bypassed by default (BYPASS_WHITELIST=True), so every caller gets long-term memory.
  • riskVoiceBridge is off by default, and classification and clarifying have no feature flag yet.
