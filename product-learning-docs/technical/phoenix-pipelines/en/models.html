Every model in EX: size, role and why

Sizes are public model facts (billions of parameters), not read from code. MoE models list total and active parameters: active parameters drive speed and cost per token.

Gemma-4 26B-A4B-it

26B total · ~4B active (MoE) · context 23K here

Live

  • Role: the main voice answer agent, intent, classifying, clarifying, end-of-turn detection, voice bridge (off).
  • Why: near-large-model understanding at ~4B-model speed, which is what a live phone turn needs (inferred).
  • Serving: gemma4-26b-llm-lb, vLLM 0.25.1, spec-decode off.

Used in these steps

  • End-of-turn detection (LLM)
  • Intent: should the call end?
  • Clarifying / small talk (speculative)
  • Route classifier
  • Main answer agent (ReAct)
  • Voice bridge (filler sentence)

How to read “B”

  • B = billions of parameters. It sets memory and quality. For MoE models (“A4B”, “A3B”) only the active part runs per token, so a 26B-A4B model decodes about as fast as a 4B dense model but needs the memory of a 26B one.
  • Context length (15K, 23K tokens here) is the most the model can read at once: system prompt + KB contexts + history + answer. It is set per deployment (--max-model-len), not by the model.
  • Token budgets per step (max output tokens, temperature) are listed on each step page when the code sets them.
Status labels: Live = in prod config and wired. Configured, off = present but disabled by a flag. Not deployed = code exists, no prod component. External = outside the cluster or outside both repos. Text marked (inferred) is reasoning, not code. Model sizes are public model facts, not read from code.
