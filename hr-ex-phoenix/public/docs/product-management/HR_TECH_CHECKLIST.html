1. System map: two pipelines

Phoenix is a monorepo (Python, Go, Rust). It has two main paths, and HR touches both: the live call with the voice assistant, and the analysis of that same call after it ends.

IVA: the live voice agent

Caller → SIP/SBC → LiveKit → chatbot-iva-agent (VAD, STT, TTS) → aiva (the brain, ReAct) → Qdrant and Postgres. The output of each call is a summary on Kafka on the topic chatbot-mci-iva.

COA: call analytics

Kafka → grogu (Go) → ASR → LLM tagging engine → ClickHouse → coa-api (Django) → coa-ui (Next.js). IVA calls also enter COA through that same topic.

3. ASR in depth

The ASR model name is not in the repository or in the Technical Dossier. The models are on Triton, and in production STT_BASE_URL probably points to neurobox-gateway (inferred). Until you ask the team, any name you give is a guess.

Live path (IVA)

Each utterance goes to STT after VAD. The client is OpenAI-compatible, with 3 retries and a ten-second timeout. Each sentence's output has a transcript_confidence.

Offline path (COA)

grogu sends the whole call file to ASR, behind a Circuit Breaker. The two tracks are converted to mono with ffmpeg and placed in one stereo MP3 file: caller on the left, Agent on the right.
