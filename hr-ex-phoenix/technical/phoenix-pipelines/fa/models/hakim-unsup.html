hakim-unsup (Hakim بدون نظارت، vLLM pooling)

فعال رمزگذار هم‌رده BERT (تأییدنشده) · 512 توکن

در یک پاراگراف برای TPM: hakim-unsup گونه‌ای از مدل embedding فارسی Hakim است که vLLM آن را در حالت «pooling» سرو می‌کند؛ یعنی به‌جای متن، بردار برمی‌گرداند. مغز صوتی EX برای هر آیتم دانش دو بار از آن استفاده می‌کند: یک بار هنگام همگام‌سازی پایگاه دانش با vector store و یک بار برای هر گفتهٔ تماس‌گیرنده در زمان پاسخ. چون هر دو طرف باید از یک مدل استفاده کنند، تغییر آن یعنی embedding دوبارهٔ تمام آیتم‌های دانش EX.

چرا آن‌جا استفاده می‌شود (استنباطی)

vLLM یک API سازگار با OpenAI به نام /v1/embeddings، batching و یک ایمیج واحد برای CPU و GPU می‌دهد. پیش‌فرض کد، مدل text-embedding-3-large از OpenAI است (phoenix:python/aiva/aiva/chat/config.py:49)، پس این انتخاب متن کارکنان را درون سازمان نگه می‌دارد.

مبادلات (Trade-offs)

  • پنجرهٔ 512 توکنی: پاسخ‌های بلند KB توسط pooler chunk می‌شوند و بردار نهایی میانگین chunkها است (استنباطی).
  • آستانهٔ جست‌وجوی CONTEXT_RETRIEVE_THRESHOLD=0.25 (:2488-2489) برای همین مدل تنظیم شده است؛ با تعویض مدل باید دوباره تنظیم شود.

ریسک‌ها و پرسش‌های باز

  • یک گونهٔ coa-proxy وجود دارد (:811-817) که در git مصرف‌کننده ندارد.
  • Upstream از نوع bare-metal یعنی 172.23.0.17:5113 روی همان میزبان پرترافیکی است که 31B اختصاصی EX را دارد.
