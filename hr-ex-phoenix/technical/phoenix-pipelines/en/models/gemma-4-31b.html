Gemma-4 31B · shared pool (gemma-4-31b-llm-lb)

Live 31B dense · 15K context here (native ~256K)

In one paragraph for a TPM: this is the platform's default high-quality model. One Envoy load balancer spreads requests over one Kubernetes vLLM pod and five bare-metal vLLM processes, all serving google/gemma-4-31B-it. It powers agents, guardrails, knowledge-base summaries and markdown conversion for about 17 services. For EX it still runs the text chatbot's agent and guardrail and the voice knowledge-base pipeline (iva_kb). The deployed context cap is 15,000 tokens, far below the model's native window, and MTP speculative decoding is turned on to make the big dense model answer faster.

What it is (model facts)

Same weights as the dedicated server: a dense ~31B model whose every parameter works on every token. Strongest in-house option for Persian understanding, tool calling and safe wording; slowest per token among Gemma-4 variants.

Why it is used there

No commit explains the choice directly. The pattern (inferred): wherever text is shown or spoken verbatim (summaries, guardrail refusals) or the step is offline (KB sync), quality matters more than latency, so the dense model is used. The EX text chatbot was created on this pool from day one (fab85123f, 2026-10-12).

Trade-offs

  • Shared capacity: cost is amortised across products, but one heavy caller raises queue time for all. vLLM metrics cannot tell which product sent the tokens.
  • 15K cap: long KB documents must be chunked before summarisation; long agent prompts plus history can overflow (HTTP 400).
  • Spec-decode: fewer slow decode steps when the draft is accepted; benefit shrinks under heavy batching (inferred).

Risks and open questions

  • Exporter coverage: 172.23.0.17:8319, 172.16.21.4:8315 and 172.23.0.4:8311 are live upstreams but not scraped; 172.23.0.17:8311/8312 are scraped and labelled 31B but belong to the zarebin pool (prod/chatbot-inference-exporter/vllm-gemma4.yaml:26-100).
  • gemma4-31b and gemma4-31b-coa are byte-identical charts apart from the name: drift risk when one is upgraded.
  • No GPU request in git: GPU count, tensor parallelism and dtype are invisible.

How to observe it

  • Envoy: envoy_cluster_upstream_rq_time (buckets 10 ms–300 s) and envoy_cluster_membership_healthy on the LB admin port 1081.
  • vLLM: vllm:prompt_tokens_total, vllm:generation_tokens_total, vllm:num_requests_waiting, vllm:spec_decode_* acceptance, grouped by model_name and instance.
  • Phoenix: projects chatbot-ex (text, prod/chatbot-ex/values.yaml:358-359) and chatbot-ex-iva.
