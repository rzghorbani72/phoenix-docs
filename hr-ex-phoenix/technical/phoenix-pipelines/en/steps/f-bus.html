Event bus, events and the task runner

Live

Everything in agentlib talks through one in-memory event bus per request. A handler declares which event types it needs; the bus runs it in the background once all of them have arrived. Errors go to an error channel instead of crashing the request.

Class
EventBus (agentlib/core/event/bus.py:25)
Scope
one bus per HTTP request (ADCS middleware calls event_bus(), adcs/common/middlewares/event_bus.py:27)
Execution
every listener runs as a background asyncio task (agentlib/runner/task.py:46-57)
Errors
sent to bus.error_chan; ADCS closes the reply stream on the first one
Retries
only via the optional DLQ (max 3 tries); EX does not use it

What and why

Think of the bus as a notice board inside one request. A component pins a note (an event, an immutable record such as EmbeddingResultEvent). Every component that said it cares about that kind of note gets a copy and runs. Nobody calls anybody directly. This is what lets aiva run intent detection, clarifying, classification, embedding and retrieval at the same time.

How it works

  1. A method is marked with @EventBus.on. The bus reads its parameter type hints to learn which event types it wants (agentlib/core/event/bus.py:92-128).
  2. When a handler object is created, EventHandlerMixin._attach_bus finds all marked methods and subscribes them (agentlib/core/mixin/event/handler.py:57-93).
  3. publish_nowait(event) schedules delivery in a background task; publish awaits it (bus.py:130-147).
  4. Join semantics: a method with several event parameters runs only after one of each has arrived, then its memory is cleared (agentlib/core/event/listener.py:51-87). Example: react_retrieve(contexts, instructions, tools) fires only when all three retrievals finished.
  5. Exact type match: delivery uses the exact event class, not subclasses (bus.py:139-143). aiva relies on this: its AIVARetrieveEvent does not trigger agentlib's own tool retriever.
  6. Tags: an event is delivered only if its tags are a subset of the listener's tags (listener.py:60). Untagged events reach everyone; an event tagged guardrail only reaches listeners declared with that tag.
  7. Any exception in a listener becomes an ExecutionError on error_chan (listener.py:73-85, runner/task.py:108-125).

Event base class

Every event is a frozen dataclass with eid, tries, tags and an optional payload (agentlib/core/schemas/event/base.py:11-32). clone() increments tries and is used by the dead-letter queue to republish (agentlib/core/event/dlq.py:28-46, default max_tries=3).

What EX uses vs not

  • Uses: the bus, join semantics, tags react / guardrail, the error channel (ADCS logs the error and closes the stream, adcs/chat/handlers/chat.py:51-55).
  • Does not use: the DLQ, wait_until_done, clear_events. A failed step is not retried by the framework.

Gotchas

One error anywhere ends the turn: the first ExecutionError makes ADCS close the stream, so the caller hears nothing more for that turn, even if another branch could still answer.
In 0.45.0, when aiva cancels a losing branch, the runner's done-callback calls exception() on a cancelled task (runner/task.py:99-104), which raises CancelledError inside the callback. asyncio logs it as an error; it does not break the turn (inferred). Fixed in 0.46.2.
Join state lives on the listener. If one of the awaited events never arrives (for example a retriever raised), the joined handler silently never runs (inferred).

What changed on main

0.46.2 makes wait_until_done drain chains of events that publish more events, ignores cancelled tasks in the runner, and stops raising when the error channel is already closed (raise_on_closed=False).
