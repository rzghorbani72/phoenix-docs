Model serving (vLLM pools)

Live

Each model is served by vLLM behind an Envoy load balancer that mixes one Kubernetes pod with several bare-metal GPU servers. One exception since 2026-11-02: the EX main agent and guardrail call a single bare-metal 31B instance directly, with no load balancer.

Gaps

  • No values file requests GPUs or sets tensor-parallel, dtype or max-num-seqs; bare-metal launch flags are not in git.
  • The dedicated 31B endpoint is a raw IP in the EX values (chatbot-ops/prod/chatbot-ex/values.yaml:1318-1327), not behind any Envoy pool: no health check, no failover. The host 172.23.0.17 also backs other pools on other ports (31B pool :8319, zarebin, COA, Qwen, embeddings), so “dedicated” means its own vLLM process, not necessarily its own GPUs (inferred).
  • Context windows (15K / 23K) are far below the models' native windows; long prompts + history can hit vLLM 400 errors.
