Sync to the vector store (every 60 s)

Live

A background job checks for new or edited Q&A every minute and indexes it. There is no publish button: an edit is live within about a minute.

Job
aiva_sync_qdrant_task, interval 60 s (default 300)
Worker
iva_kb_worker, concurrency 1
Broker
Redis chatbot-ex-redis db 1
Re-index
scripts/run_kb_sync.sh

Logic

  1. Select answers that are stale (qdrant_last_sync < updated_at, never synced, or flagged) and eligible (active and inside the time window) (models/answer.py:52-60).
  2. Gather each answer's valid questions; an answer with 0 questions is soft-deleted and its vector removed (handlers/qdrant/sync.py:100-120).
  3. Skip re-embedding when the SHA-256 of the payload is unchanged.
  4. Embed (K4) and upsert (K5); mark rows synced.
  5. Guardrails and suggestions are synced the same way into their own collections.

Failure

A Qdrant or embedding error is logged and the rows stay unsynced, so the next tick retries. Old vectors stay live meanwhile. Changing the embedding model needs a manual full re-embed, because the hash does not include the model id (inferred).
