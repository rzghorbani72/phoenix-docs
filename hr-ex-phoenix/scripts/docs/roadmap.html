How to think, how to lead the team, what to build, and which technical direction to take the project in

Audience: all project members · Version 0.1 · 5 Oct 2026 · Basis: repository code (reviewed 29 Sep 2026), the EX pilot Fit-Gap agreement, and the competitor analysis in chapter 25 of PRODUCT_DOSSIER_FA.pdf

1. On one page

Product thesis: "A Persian voice listening and conversation channel for deskless employees that runs inside the organization and connects to the existing HRIS instead of replacing it." None of the 13 major global HCM vendors and no Iranian competitor has this combination (dossier 25.5 and 25.5b).
  1. The engine is built; trust is not. The Voice Agent, Orchestrator, call analytics, Trend and AQA are real and of good quality; but de-identification, a small-group threshold, an Audit Log and audio ownership control do not exist. These are exactly what an HR buyer pays for. FIT-GAP PRV-01/03/05/06/09
  2. Today's "SaaS" is not SaaS. The code has no notion of a Tenant, and a separate deployment has been built for each customer (chatbot-mci, chatbot-tejarat, chatbot-mobinnet). For Iran's government and large-enterprise market this is an advantage, not a flaw: for now the right model is "managed private deployment". CODE grep tenant → 0
  3. The team is small and concentrated on one person. About 10 people work on the core services; one person has made ~42% of the commits and two people ~58% since late June 2026. Several chatbots for other customers are being maintained at the same time. GIT shortlog since 2026-06-28
  4. The right order: first pass the buying test (trust), then prove the pilot with numbers, then sell a second product to the same customer, and only after that "productize" for a second customer.

2. How to think: eight decision principles

# Principle What it means in practice
1One buyer, one problem, one numberEvery feature must tie to a written EX problem and one measurable metric; "it's interesting" is not a reason to build.
2"Implemented" ≠ "measured"STT exists but WER has never been measured; summaries exist but faithfulness has not been measured (AI-01, AI-03). No AI feature counts as delivered without an Eval.
3Trust before intelligenceIn HR, Privacy and Audit are selling features, not a cost. Until PRV is closed, we build no new AI features.
4No dependency, no deadlineEvery commitment is "T + n business days after receiving X" (rule TEC-14).
5A layer on top of the HRIS, not an HRIS competitorWe do not compete with Rahkaran, Didgah or SAP; the first integration is read-only and file-based. Payroll and personnel records, never.
6Product = configuration of one corePulse, Exit Interview, Helpdesk and Onboarding are one engine with different prompts, knowledge, tools and taxonomies. If a second product needs a lot of new code, the architecture is wrong.
7Build differentiation where competitors cannotPersian telephony, on-premises, deskless employees. "A helpdesk that only answers" will soon be a commodity (all 13 HCM vendors have one).
8Evidence, not demosThe go/stop decision for each wave is made with numbers (TEC-15), and a demo is always a real scenario with an exception.

5. How to lead the team

A) Structure: three streams with clear owners

Stream Scope Health metric
Trust and platformadcs-auth, Audit, de-identification, k threshold, deployment, security, capacityZero identity leaks in testing; 100% of access in the Log; customer onboarding time
Conversationchatbot-iva-agent, aiva, agentlib, knowledge, outbound callingCompleted-call rate; WER; response latency; human-handoff rate
Insightcoa-api, Trend, aqa, sentiment and topic modelsTopic accuracy; summary faithfulness; time to insight
Knowledge-concentration risk: with ~42% of commits concentrated on one person, every stream should have a trained second owner; CODEOWNERS with two names for each service; Pair Programming on aiva in waves 0 and 1. INFERENCE from GIT

B) Focus and capacity

  • Make the capacity cap for other customers' chatbots explicit (e.g. 20%) so that waves 0 and 1 are not sacrificed to scattered requests INFERENCE.
  • 20% of each Sprint's capacity for technical debt and security; in wave 0 this number is higher.
  • Every new task must link to a Fit-Gap row or a numbered idea in chapter 25.

D) Definition of "done" for every AI feature

  1. A test set and metric with a baseline number.
  2. Tracing in Phoenix/OpenTelemetry (the existing pattern in aqa and adcs-knowledgebase).
  3. Privacy review: what data is stored, who sees it.
  4. Cost per call or per request measured.
  5. A Rollback path and a kill-switch Flag.

E) Decision rules: build, partner, or don't build

Decision When… Example
BuildIt strengthens our differentiation and more than 70% of it comes from the existing core.Pulse, Exit Interview, Copilot, Persian sentiment model
PartnerThe data or its license belongs to someone else.HRIS (Chargoon, Hamkaran System), voice biometrics, ATS
Don't buildA competitor has superior data or distribution, or it is an ethical red line.Payroll, skills graph, individual risk scores, Passive Listening
StopAfter two rounds, the target metric has not moved.Any idea from wave 2 onward

6. How to steer the project technically

# Technical direction Action Wave
1Privacy at the input, not the outputDe-identification before storage, in the Kafka consumption path and once for all services; Audit as a shared Middleware in adcs; k threshold at the Query layer (both coa-api and the AQA Views).0
2Eval as a release gateThree layers: offline Eval on every Commit, a golden set of ~10 Persian calls that blocks Deploy, and daily monitoring on real Traces (the Rippling pattern). Bring the aqa/api/routers/evaluation/run.py pattern to IVA and AIVA.1
3Uniform ObservabilityExtend the current Tracing in aqa and knowledge to aiva and chatbot-iva-agent; cost, latency and outcome of each Turn in one dashboard.1
4"Scenario" as dataThe definition of each product (Prompt, knowledge, Tool, Taxonomy, privacy policy, KPI) in one versioned model instead of environment variables; the basis for a Studio and fast deployment.2–3
5The LLM never invents valuesFor actions: Slots with a Resolver from the system of record, verbal confirmation before a Write, Idempotency; upgrade the current Clarifying (aiva/chat/utils/agents.py:148).2
6Integration with a clear contractFiles first, with a Validator and error report; then MCP (the existing Client in agentlib-plugin-mcp); an MCP Server for aggregated Insight export.2–3
7Capacity and loadLift the Celery cap of concurrency=1 (TEC-02); load test with the existing websocall script before outbound calling.1–2
8Cost per call5 to 7 LLM calls per Turn; route simple tasks (sentiment, classification) to a small model; keep the Prompt stable for the Cache that already exists.1–2
9Hidden debtAn explicit decision on the frozen coa-ai (last commit in mid-2025), which holds the topic-tagging logic.1
10Resilience without internetList all external runtime dependencies (APIs, models, Packages), remove them, and run periodic internet-outage drills.3
11Multi-customer without multi-tenancyA separate Chart and Values per customer, configuration as data, and a one-week onboarding checklist. True Tenancy only with a decision to enter the SMB market.3
